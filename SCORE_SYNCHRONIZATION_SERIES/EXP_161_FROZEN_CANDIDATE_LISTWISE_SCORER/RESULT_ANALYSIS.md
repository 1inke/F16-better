# EXP-161 冻结候选独立评分校准结果

## Decision: REJECTED

当前这套 residual listwise scorer 在 V2、M2 和全部五个 held-out fold 上均未通过评分同步门槛，因此不能替换原始 score head，也不能据此冻结最终解码器。

## 宏平均结果

| 候选族 | Oracle minADE/minFDE | 原始 Top-1 ADE/FDE | 同步后 Top-1 ADE/FDE | ADE/FDE 变化 | Regret 变化 |
|---|---:|---:|---:|---:|---:|
| V2 | 0.2225 / 0.3649 | 0.5160 / 1.0648 | 0.5776 / 1.2167 | **退化 11.94% / 14.27%** | **退化 21.73%** |
| M2 | 0.2200 / 0.3635 | 0.5155 / 1.0743 | 0.5718 / 1.2023 | **退化 10.93% / 11.92%** | **退化 19.09%** |

V2 五折 Top-1 ADE/FDE 全部退化，M2 也在五折全部退化。退化不是单个数据集异常，也不是随机波动。

## 关键诊断

1. 训练集内部 validation loss 在大多数折持续下降，held-out 场景却统一退化。这说明评分器不是没有拟合，而是学到了不能跨场景泛化的候选排序规律。
2. V2 combined-winner hit 从 15.46% 上升到 21.20%，但 mean regret 反而增加 21.73%；M2 也有相同现象。新评分器更频繁地精确命中部分容易样本，但一旦选错，就会选择代价更大的候选，形成高风险尾部错误。
3. V2 Spearman 从 0.7476 降到 0.5950，M2 从 0.7319 降到 0.6009，说明对全部 20 条候选的整体排序质量下降，并非仅 Top-1 阈值问题。
4. score entropy 分别只保留 83.01% 和 85.88%。活跃 Top-1 mode 数量增加，但概率分布更尖锐，说明“使用更多模式”没有转化为更稳健的概率校准。
5. 当前 soft-listwise 目标温度为 0.10，容易强调每个训练样本的局部 winner；随机划分的训练内部验证集与训练集同域，无法阻止这种规则在 held-out 场景失效。

## V2 与 M2 的候选质量

评分器失败不改变冻结候选本身的 oracle 结果。相对 V2，M2 宏平均：

- minADE 改善约 **1.10%**；
- minFDE 改善约 **0.37%**；
- same-path FDE 改善约 **0.76%**；
- 原始 Top-1 ADE 改善约 **0.10%**；
- 原始 Top-1 FDE 退化约 **0.89%**；
- 原始 Top-1 combined cost 退化约 **0.23%**。

M2 的 minADE 在 ETH、Univ、Zara1、Zara2 四折优于 V2，但 Hotel 退化；minFDE 收益更小且逐折方向不完全一致。因此 M2 是一个小幅 accuracy variant，而不是已经证明具有稳定综合优势的最终解码器。

相对 matched K20，M2 的官方五折宏平均 minADE/minFDE 约改善 6.84%/18.05%，但收益主要来自 ETH；在 Univ 上反而退化约 8.71%/12.52%。由于 Univ 样本很多，sample-weighted minADE/minFDE 相对 K20 反而退化约 6.37%/7.72%。正式 benchmark 仍应报告五数据集宏平均，但这个结果说明跨 fold 稳定性尚未解决，不能只依据宏平均宣布最终模型已经冻结。

## 当前决策

- **拒绝 EXP-161 当前评分器**，保留原始 score head。
- **主模型暂时优先 V2**：其结构更简单，原始 Top-1 FDE 和 combined cost 略好，而 M2 的平均 oracle 增益不足 1%（ADE/FDE 两项平均约 0.74%）。
- **M2 保留为 accuracy ablation**：如果论文主目标严格优先 minADE，可报告其约 1.1% 的 minADE 增益，但不应描述为全面优于 V2。
- 暂不启动 seeds 2/3 的最终 15-run 验证；当前“score mismatch 已处理”的前置条件尚未满足。

## 后续含义

本结果没有证明候选几何无效；它证明的是“在 fold 的训练场景上随机划分验证集、用尖锐 listwise winner 目标训练独立评分器”不能泛化到被留出的新场景。若继续解决评分问题，应优先改变验证与目标设计，而不是增大评分器：使用跨场景 validation、降低目标尖锐度，并直接约束相对原始评分的 regret/tail regression。
