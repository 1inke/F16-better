# 注意力计算机制第二轮实验最终报告

## 1. 最终结论

本轮实现并训练了四种新的注意力计算机制，并针对唯一有潜力的 F38 增加了多种子、跨场景和训练调度实验。

1. **默认模型仍为 F16 + K20。** 没有新方法同时在三种子 Original ADE、跨场景泛化和训练稳定性上稳定超过 F16。
2. **F38“早期池化 + 近期精确保留”是本轮唯一保留的研究候选。** 它把 8 个历史 K/V 压为 3 个，在最佳 checkpoint 的五场景加权结果上达到 0.4159/0.8778，优于同规则 F16 的 0.4224/0.8854；但三种子 Original ADE 均值略弱，并且第 30 轮容易退化。
3. **F39 单轨迹加速度事件采样失败。** 来源行人的自身加速度峰值不是稳定的目标—邻居交互关键时刻。
4. **F40 速度相似度 Token Squeezing 失败。** 它会合并时间相隔较远但速度相似的状态，削弱阶段顺序。
5. **F41 边列表注意力通过严格等价检查，但没有真实加速。** 在当前约 9 个行人的小张量上，gather/scatter 开销抵消了稀疏计算收益。
6. **单调余弦没有解决 F38 的训练敏感性。** 它改善第 30 轮退化，但没有超过 F16，也没有复现 warm-restart seed 1 的早期高峰。

|---|---:|---:|---:|---|

## 3. F38 三种子复验

每个种子使用每 5 轮验证一次所保存的最佳 Original ADE checkpoint：

| 方法 | Original ADE/FDE | Fused ADE/FDE | minADE20/minFDE20 |
|---|---:|---:|---:|
| F16 | **0.4518 / 0.8031** | 0.4212 / 0.7533 | **0.1598 / 0.2550** |
| F35 | 0.4542 / 0.8183 | 0.4220 / 0.7666 | 0.1577 / **0.2480** |
| F38 | 0.4600 / **0.8031** | **0.4190 / 0.7408** | 0.1618 / 0.2504 |

F38 的 seed 1 大幅优势没有完整复现。它的三种子 Original ADE 比 F16 弱约 1.8%，FDE相同；Fused ADE/FDE 分别改善约 0.5%/1.7%。因此不能依据 seed 1 把 F38 宣称为稳定提升。

## 4. F38 五场景泛化

seed 1，各场景采用统一的最佳验证 checkpoint 规则，按验证样本数加权：

| 方法 | 加权 ADE/FDE | 加权 minADE20 |
|---|---:|---:|
| F16 | 0.4224 / 0.8854 | 0.2017 |
| F35 | 0.4221 / 0.8874 | 0.1996 |
| F38 | **0.4159 / 0.8778** | **0.1971** |

F38 相对 F16 改善约 1.5% ADE 和 0.9% FDE。但固定使用第 30 轮时，F38 为 0.4826/0.9849，弱于 F16 的 0.4737/0.9802。它的结构潜力依赖 checkpoint 选择，尚未转化成稳定训练优势。

## 5. 计算规模

在 N=9、T=8、d=96、H=4 下，仅统计 temporal-social attention 的 Q/K/V、QK、AV 和输出投影主要 MAC：

| 方法 | K/V 时间 token | score 元素 | 注意力核心主要 MAC | 相对 F16 |
|---|---:|---:|---:|---:|
| F16 | 8 | 2,592 | 1,617,408 | 基线 |
| F35 | 2 | 648 | 528,768 | -67.3% |
| F38/F39 | 3 | 972 | 710,208 | -56.1% |
| F40 | 4 | 1,296 | 891,648 | -44.9% |

F39 另有加速度计算与动态 gather，F40 另有中心选择、距离和 token 归属计算，因此表中数值是注意力核心而不是完整模块开销。

## 6. 统一 CUDA 基准

12 轮交错、每轮旋转模型顺序；下表为均值：

| 方法 | batch=1 延迟 | batch=64 延迟 | batch=64 峰值前向显存 |
|---|---:|---:|---:|
| F16 | **10.13 ms** | 13.83 ms | 61.28 MB |
| F35 | 10.54 ms | 13.67 ms | 57.23 MB |
| F38 | 10.75 ms | 13.71 ms | 57.23 MB |
| F39 | 10.58 ms | **13.63 ms** | 57.23 MB |
| F40 | 10.65 ms | 13.81 ms | 57.23 MB |
| F41 | 10.36 ms | 14.36 ms | 57.23 MB |

F38/F39/F40 相对 F16 的峰值前向显存下降约 6.6%，但延迟差异落在运行波动范围内。F41 在 batch=64 约慢 3.9%，证明普通 PyTorch 边列表 gather/scatter 不适合当前小 N；只有更大行人数或融合稀疏 kernel 才值得继续。

## 7. F41 严格等价验证

F16 与 F41 加载完全相同的权重，在包含 9、6、3 个有效行人的混合 batch 上：

- 最大预测绝对差：8.34e-7；
- 最大模式 logits 绝对差：2.61e-7。

因此 F41 的前向数学语义等价。不同训练轨迹来自浮点求和顺序的微小差异被非凸训练放大，不能被解释为新的建模差异。

## 8. 后续建议

### 默认与部署候选

- 默认跨场景模型：F16 + K20。
- 显存优先且要求稳定：F35 + K20。
- F38 暂只作为研究候选，不替换默认主干。

### 若继续研究 F38

下一步不应再改注意力表达，而应解决优化稳定性：

1. 使用独立训练集内部划分做 early stopping，避免直接用完整验证场景挑 checkpoint；
2. 测试更低峰值学习率，而不是只替换调度曲线；
3. 检查 mode logits 校准，因为 F38 的 oracle 与 Fused 信号优于 Original 排序的程度不一致；
4. 若重新做事件采样，使用目标—邻居成对 TTC/DCA 事件，并保留近期两帧，不再使用单源加速度峰值。
