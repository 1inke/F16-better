# 曲线可达性分类诊断：完成分析（2026-10-04）

## 结论先行

当前单脉冲曲线在**同样native K20、同样修正范围**内，对绝大多数FIT/CAL窗口可以构造出满足同一完整候选 ADE≤0.2m AND FDE≤0.4m 的路径。因此，现阶段不能再把主要失败笼统归结为“曲线画不出来”。更值得优先研究的是**观测条件→候选响应参数的学习，以及原目标/保护项如何驱动或阻碍覆盖**。这是一项优先级判断，不是已经定位唯一根因。

GT辅助构造知道未来，并且能为每个窗口、每个slot独立选参数；共享预测head没有这个条件。因此，下面的99%左右是**表达可行证据覆盖**，绝不是预测准确率、可达SOTA性能或“99%未来可预测”。

## 4. 全体实际模型与有效候选数量

全体FIT native覆盖14867/25912（57.38%），learned15167/15082/15001（58.53%/58.20%/57.89%）。全体CAL native1490/2879（51.75%），learned1485/1507/1495（51.58%/52.34%/51.93%）。CAL分别救回48/40/31，同时丢失53/23/26，净−5/+17/+5。表达证据的高比例没有转化为显著实际覆盖改善。[RESULT](RESULT.json)

GT无关去重固定为全K20 complete-link几何meanpath≤.10m、endpoint≤.20m，另保留两种预设敏感性，不以GT作为聚类依据。

- CAL第一事件相容137中，native31个覆盖：28例只有1个有效好簇、3例≥2。learned32/34/30例覆盖，其中30/31/27例只有1个好簇、2/3/3例≥2；这一研究池原始好数与有效好数相同。主要问题仍是**从0到1**，不是复制候选导致很多虚假有效数量。
- CAL粗响应路径失败77例，learned覆盖3/3/1且这些均只有1个有效好簇。
- 知道GT的pulse构造在这77例平均16.21个原始好候选，但去重后只有2.96个有效好簇。GT辅助把许多slot拉近GT会制造冗余；不能把16.21当部署目标或鼓励所有20条收拢。逐步superset平均19.61个原始好、有效1.31，恰好说明“原始好数更多”不等“有用多样性更多”。

因此阶段目标保持：**先覆盖≥1个完整好候选；再研究GT无关有效好数量与合法替代未来；最后scorer**。本轮没有任何scorer改进/argmax部署收益结论。

## 5. 资源与方法边界

[RESOURCE_USAGE](RESOURCE_USAGE.json)记录采样峰值RSS1.332GiB、private1.716GiB；进程生命周期峰值RSS1.358GiB、private1.741GiB。采样系统最小physical余量16.081GiB、commit余量15.958GiB，低于预检峰值也只是此运行条件，不保证未来任务恒定。均在6GiB过程预算、系统各6GiB余量要求内。人类约17GB可用hostRAM约束继续长期有效，不调整OS/pagefile/停止他人程序。

局限必须保留：

1. GT辅助独立设置每窗口/每slot参数，不受共享head可学习性、观测未来歧义或训练泛化限制。能画出来不等能预测出来。
2. 构造只证明严格位置误差、当前clip/几何表达条件；没有证明这些oracle满足原全部loss/保护/校准与所有组运动学1%约束。即使覆盖高，也不是完整“高质量可部署模型”。
3. 三锁定constrained模型是原CAL选择epoch34/26/18，不是final80epoch，也没有据本次oracle结果重选checkpoint。FIT见过、CAL用于选择且只有university；三scene不均衡、窗口/track相关、future-completeness邻居资格偏差不变。不报可靠groupCI/p值，不把三seed当独立人。
4. 原free12increments/timequery/velocitybasis失败、旧三anchor GT可达、tinyFIT好CAL差、脉冲严格DEV覆盖下降与运动学失败均是反证。当前结果削弱“必须更自由曲线”解释，但不证明decoder或原损失就是唯一根因，也不否定未来合理架构改进。
5. 没有删除低线索/困难样例，没有修改官方评测集，没有DEV/test新读取；正式response study仍2/3，不计此诊断为第三formal实验。

## 6. 下一步建议：先查原学习目标是否推动正确响应

本轮计划已完成，当前等人类讨论，不自动新训练。

建议下一个**不训练、FIT/CAL-only**诊断先做“原目标对可行好候选的偏好/梯度分配”审查：比较native、实际learned、GT辅助完整构造，以及只替换一个见证slot而保留另外19个的反事实输入；按不变原质量项/原regularizers/protection分解标量、赢家slot、哪条候选收到梯度、保护代价及运动学。GT仅事后诊断，不进入真实预测forward。

这个设计的目的不是用GT生成teacher自动开始新loss训练，而是先区分：原目标确实奖励完整好候选但head未学出，还是质量目标/赢家/保护相互作用让“严格好路径”并非原优化更偏好的解。若oracle只在违反运动学/保护时可用，也需要明确归类，而不能放宽保护来强称成功。多解参数不可辨识，不能直接把拟合中心/跨度当真实onset/duration，更不能盲回归这些codes。

实施前须另行确认精确诊断范围与预算。任何需要新loss/事件监督/更广解冻/新数据，必须停下来等待具体人类决定。原major、全组motion1%标准维持；不从本结果自动开第三formal训练。
