# EXP-139 无 CV 层次化解码实验结果分析

## 1. 实验状态

- 4 个新解码器 × General/Challenge × 3 seeds，共 24 次新训练，已全部完成。
- Baseline 使用既有的同协议 3-seed 结果，不重复训练。
- 所有新解码器均不使用 CV 外推；终点和中间锚点由模型直接生成。
- 表中均为 3 seeds 的均值；所有误差指标越低越好。

## 3. 主要判断

### 3.1 三锚点生成是本轮唯一应保留的方案

只生成终点会造成明显的 ADE/FDE 冲突：它能把终点候选铺开，因此 FDE 下降，但终点之间的轨迹仅靠线性连接，路径中段缺少约束，General/Challenge 的 minADE 分别恶化 14.95% 和 7.22%。

加入第 4、8、12 步三个学习式锚点后，Challenge 的 minADE 和 minFDE 同时改善，说明行人未来轨迹确实需要中间状态表达，而不是只用终点决定整条路径。三锚点也使同一路径 FDE 大幅下降，证明改善不是由两个不同候选分别刷出 minADE 和 minFDE，而是单条候选的整体质量提高。

### 3.2 当前选择-细化模块没有带来净收益

- 终点细化相对终点生成可降低 minADE，但会损害 minFDE；它只是部分缓解终点方案的路径中段问题。
- 三锚点细化相对三锚点生成，在 General 和 Challenge 上的 minADE、minFDE 均变差。
- 三锚点细化器对已入选粗轨迹的 minADE 平均只改善约 0.0029（General）和 0.0015（Challenge），收益很小。
- 三锚点粗轨迹的 Oracle 候选进入 Top-8 的召回率只有 69.2%（General）和 53.6%（Challenge）。大量最佳粗候选在细化前已被筛掉，后续细化器无法补救。
- 因为终点被严格保持，细化前后的 minFDE 差值恒为 0；联合训练却可能改变上游候选分布，所以最终模型的 minFDE仍可能比纯生成版本更差。

因此，不能把 EXP-139D 作为新基线。它增加约 11.9% 参数（相对三锚点生成），却没有获得对应性能收益。

### 3.3 新结构改善了候选质量，但没有改善候选排序

三锚点生成在 Challenge 上有很强的 Oracle 指标提升，但 Top-1 ADE 仍比 Baseline 差约 1.0%。这说明当前获得的是“20条候选中存在更好的轨迹”，而不是“模型更容易把最佳轨迹排在第一”。候选生成和候选评分仍是两个不同问题。

### 3.4 参数成本较低

- 三锚点生成：295,474 参数，仅比 Baseline 增加 10,832，约 +3.81%。
- 三锚点选择-细化：330,548 参数，比 Baseline 增加约 16.13%。

因此，三锚点生成取得的 Challenge 改善具有较好的轻量化性价比；细化版本目前不具备这种性价比。

## 4. 最终结论

本轮验证支持“先生成学习式中间锚点，再构造完整轨迹”的核心假设，但不支持当前的 Top-8 选择-细化实现。

建议将 `EXP_139C_THREE_ANCHOR_PROPOSAL_ONLY` 作为下一轮解码研究起点，保留三锚点生成，暂时移除当前细化器。下一轮应优先解决：

1. 在不破坏终点覆盖的前提下改善锚点之间的局部轨迹细节；
2. 避免 Top-8 硬筛选造成 Oracle 候选丢失；
3. 将候选评分与同一路径 ADE/FDE 质量对齐；
4. 验证 General minADE 能否在保持 FDE 优势的同时进一步下降。

不建议继续通过扩大当前细化器、增加细化层数或单纯调整 Top-8 超参数进行大规模搜索；现有结果表明主要瓶颈是筛选召回和训练耦合，而不是细化器容量不足。
