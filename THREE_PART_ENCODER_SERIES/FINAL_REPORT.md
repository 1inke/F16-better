# 输入、运动学与时间编码三部分改进报告

## 1. 固定协议

- F16 稀疏时序—社会注意力
- Kinematic K20 解码器
- Coverage Loss 0.20
- EMA 0.995
- 30 epoch，Oracle-aware检查点
- 先用scene 1和scene 3筛选，再做三种子及内部五场景复验

这些实验没有修改K20解码器和20候选生成形式。

## 2. 三部分结论

### A. 输入坐标：目标航向规范化有效

最佳配置为EXP-102/111：

1. 目标最后位置作为原点；
2. 最近3个观测间隔的平滑位移作为x轴；
3. 全场历史、未来和构图坐标统一旋转；
4. 50%概率镜像和0.9–1.1速度缩放；
5. 不再使用随机全局旋转。

五场景加权相对原半概率增强主线：

| 指标 | 原主线 | 航向规范化 | 变化 |
|---|---:|---:|---:|
| minADE20 | 0.182086 | **0.174011** | -4.4% |
| 同路径FDE | 0.403683 | **0.394404** | -2.3% |
| minFDE20 | 0.334799 | **0.332367** | -0.7% |

但scene 1三种子minADE从0.130107退化到0.136079，所以它更适合跨场景泛化，而非每个场景均占优。

### B. 运动学状态：单独扩展失败，和局部坐标组合部分有效

EXP-103新增jerk、加速度幅值、速度趋势、静止概率和通道门控：

- scene 1：0.133679/0.217109
- scene 3：0.197243/0.365154
- 参数增至288,277

单独使用全面落后，说明8帧历史上的高阶差分噪声较大。

与航向规范化组合后，EXP-104 scene 1达到0.131237/0.209717，minFDE很强，但scene 3的FDE不如更简单的EXP-102。结论是局部坐标能帮助运动状态解释，但新增参数没有形成统一优势。

### C. 时间编码：Masked History跨场景有效，但种子不稳定

EXP-105使用15%历史中间帧遮挡、恢复权重0.05：

- 五场景加权 minADE：0.182086 → 0.179341
- 同路径 FDE：0.403683 → 0.396323
- minFDE：0.334799 → **0.328948**

但scene 1三种子minFDE标准差从0.00246升至0.01035，seed 2明显失败，因此不能直接入选稳定主线。

把遮挡概率降到10%后，scene 1三种子为：

- minADE：0.131080 ± 0.002349
- 同路径 FDE：0.246112 ± 0.006607
- minFDE：0.212554 ± 0.003963

方差下降且minFDE均值改善，但minADE仍略退。定位为FDE优先的可选训练策略。

## 3. 当前三套配置

### 跨场景Oracle精度版

`F16 + 航向规范化 + 50%镜像/速度缩放 + Coverage 0.20 + EMA`

- 参数：284,642
- 内部五场景加权：0.174011 / 0.332367
- 当前最低加权minADE

### 单场景稳定版

`F16 + 50%旋转/镜像/速度增强 + Coverage 0.20 + EMA`

- 参数：284,642
- scene 1三种子：0.130107 ± 0.000938 / 0.214219 ± 0.002456
- minADE方差最低

### FDE探索版

`稳定版 + Masked History(probability=0.10, weight=0.05)`

- 推理参数仍为284,642
- scene 1三种子minFDE：0.212554
- 尚不替换主线，因为minADE和方差略差

## 4. 失败与保留方向

| 方法 | 判定 |
|---|---|
| 纯航向规范化、无正则 | minADE/FDE权衡明显 |
| 航向规范化+镜像/速度 | 跨场景胜者 |
| 高阶运动学特征单独使用 | 淘汰 |
| 高阶运动学+航向规范化 | scene 1 FDE候选，不优先 |
| Masked History 15% | 加权指标强但种子不稳定 |
| Masked History 10% | FDE候选 |
| Masked History权重0.02/0.10 | 均不如0.05 |

## 5. 重要限制

五个scene仍是`univ_data_train.npy`内部scene ID，并非官方ETH/Hotel/Univ/Zara1/Zara2五折。航向规范化是否成为论文最终模型，必须通过官方五数据集leave-one-out验证。
