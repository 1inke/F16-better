# 注意力与结构编码自主探索总报告

## 1. 最重要的结论

本轮在固定 K20 运动学解码器、固定训练协议和尽量保持原稀疏交互图的条件下，系统比较了动态路由、结构编码、注意力偏置、稀疏归一化、代理注意力、时间—社交交叉注意力及其组合。

**唯一同时满足“提升明显、三种随机种子稳定、参数几乎不增加”的主候选是 F16 时间—社交交叉注意力。** 它不再把邻居历史压缩成单个摘要后交互，而是让目标摘要在原稀疏邻接约束下访问邻居的各个观测时刻。改进来自保留交互发生的时间信息，而非扩大模型容量。

建议当前主干采用：

> F10 多尺度运动编码 + F16 稀疏时间—社交交叉注意力 + 固定 K20 运动学解码器。

不要把动态路由、节点结构嵌入、Agent proxy、关系调制 Q/K 或场景人数硬门控并入主干；这些方法在当前数据与训练规模下没有稳定收益。

## 2. 三种随机种子的核心证据（scene 1）

| 方法 | 参数量 | Original ADE/FDE（均值） | Fused ADE/FDE（均值） | minADE20/minFDE20（均值） |
|---|---:|---:|---:|---:|
| F4 + K20 基线 | 284,541 | 0.5400 / 0.9342 | 0.4593 / 0.8109 | 0.1658 / 0.2553 |
| F16 时间—社交交叉 | 284,642 | **0.4948 / 0.8770** | **0.4338 / 0.7833** | 0.1641 / 0.2616 |

F16 相对 F4 的均值变化：Original ADE 改善约 8.4%，Original FDE 改善约 6.1%，Fused ADE 改善约 5.6%，Fused FDE 改善约 3.4%。总参数仅增加 101（约 0.036%）。三次 Fused ADE 为 0.4289、0.4351、0.4374，波动很小。

oracle 指标没有同步大幅改善，说明 F16 的主要贡献是让编码表征更利于候选模式排序和选择，而不是单纯扩大候选轨迹的覆盖范围。这也解释了为什么它能与既有运动学解码器协同，而无需先修改解码器。

## 3. 跨场景证据

F16 与 F4 在 seed=1 下完成了五个留一场景比较。

| 汇总方式 | F4 Original ADE/FDE | F16 Original ADE/FDE | F4 minADE20 | F16 minADE20 |
|---|---:|---:|---:|---:|
| 场景宏平均 | 0.6246 / 1.2494 | 0.6245 / 1.2620 | **0.2747** | 0.2782 |
| 按样本数加权 | 0.4864 / 0.9944 | **0.4737 / 0.9802** | **0.1984** | 0.1996 |

在具有 verifier 的场景上，样本加权 Fused ADE/FDE 从 0.4380/0.9137 改善到 0.4315/0.9097。F16 在 scene 1、3、4 获益，在极稀疏的 scene 0 退化；scene 2 则 ADE 改善但 FDE 略差。因此它是总体更好的主干，但不是每个场景都严格占优。

scene 0 的平均有效人数仅 1.68，而 scene 4 为 6.54。随后测试的 F27“按全局有效人数硬切换”仍然失败（Fused ADE 0.4604），证明简单人数阈值不足以解决域差异。若未来做自适应，应使用目标级局部邻域特征和连续门控，而不是场景级硬路由。

## 5. 为什么许多“新方法”没有奏效

1. **数据规模与结构统计不足。** 动态路由、结构嵌入和 Agent token 增加了可学习自由度，但训练样本与每幕人数有限，学习到的路由容易变成额外噪声。
2. **原始稀疏图已经提供了强先验。** 在这个基础上再做 learned routing，可能删除原本有用的物理邻居；F13 的跨种子不稳定支持这一点。
3. **关系特征更适合决定“看谁”，不一定适合重写 Q/K 内容。** F18 首轮漂亮但三种子均值优势消失，并付出明显参数成本。
4. **当前瓶颈主要不是候选覆盖。** sparsemax/entmax 常改善 minADE，却没有改善最终 ADE，表明主要矛盾是候选打分、选择和交互时序表征。
5. **机制简单叠加并不互补。** F22、F23 都弱于单独 F16。每引入一个新机制都会改变优化几何，不能依据单项直觉直接相加。

## 6. 轻量化与计算成本

F16 的参数量与 F10 相同（284,642），仅比 F4 多 101。scene 1 的一次 30-epoch 训练耗时约 202–210 秒；F4 的相同 K20 实验约 196 秒，观察到的训练耗时增幅约 3%–7%。这个数字受机器状态影响，只能作为本机粗略成本指标。

参数轻量不等于计算完全相同：F16 让每个目标访问邻居的多个历史时刻，注意力 token 数比摘要式社交注意力更大。它仍使用同一稀疏邻接掩码，并未改成全局稠密交互；但正式部署前仍应单独测量 batch=1 延迟、峰值显存和吞吐量。

## 7. 与已读论文及跨领域方法的对应

本轮使用 literature-map 将用户笔记中的 BiFormer、Attending to Graph Transformers、MART、Near-aware、STP、Forecast-MAE 等思路，和视觉/图学习中的动态稀疏路由、Agent attention、结构偏置、DropKey、稀疏归一化逐一映射到可控实验。最终有效的不是最复杂的结构，而是“保留邻居历史时间分辨率”这一较朴素的改动。

完整的论文—实验对应关系见 `ATTENTION_LITERATURE_TO_EXPERIMENT_MAP.md`。这一结果也给后续检索设定了更窄的目标：优先寻找**时空 token 压缩、局部时序交互、轻量轨迹编码和候选排序校准**，而不是继续泛化搜索新的通用注意力模块。

## 8. 下一阶段建议（按优先级）

1. **将 F16 定为新的编码主干并完整复验。** 补齐所有 scene 的 3 seeds；当前跨场景只有 seed=1，不能把加权优势当成最终结论。
2. **重新训练与 F16 匹配的 verifier。** 现有 verifier 针对旧候选分布训练；F16 的主要收益恰好是排序表征，重训可能进一步释放收益。
3. **做目标级局部连续门控，但仅作为小规模支线。** 门控输入应包含局部邻居数、最近距离、相对速度、TTC 和历史可见率，并以 F16 为残差主路。F27 已证明场景人数硬切换不可取。
4. **尝试无参数或极少参数的历史 token 压缩。** 例如只保留最近时刻、速度突变时刻及最接近时刻，让 F16 的 token 数从 `N×T` 降到 `N×K_t`，目标是在不损失精度的情况下减少延迟。
5. **最后再考虑解码器。** 当前实验已把收益明确定位到编码/交互侧；不要同时修改解码器，否则无法归因。

## 9. 最终判定

本轮没有发现单场景上“巨幅且跨场景普适”的结构模块，但找到了一个可信、轻量、可复现的编码改进：F16。它在三种子核心场景上有 5%–8% 的主要指标收益，在全场景按样本加权后仍有约 1%–3% 的收益，且参数几乎不变。现阶段应从“继续横向堆叠更多注意力变体”转向“完整复验 F16、重训 verifier、压缩 F16 的历史 token 成本”。

需要保留的备选支线只有 F17/F33（偏向改善候选覆盖）；其余方向均已有否定证据，不建议重复投入。
