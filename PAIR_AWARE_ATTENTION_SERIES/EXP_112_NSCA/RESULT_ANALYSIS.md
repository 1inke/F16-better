# EXP-112 NSCA 结果分析

## 结论

NSCA 未通过跨场景首筛，不替换 F16。它在 scene 1 同时改善三个 Oracle 指标，但在样本更多的 scene 3 同时退化；两场景样本加权后 Oracle 全部略差。

## 诊断

1. Q/K 模长不是可以无条件删除的噪声。scene 1 的归一化有利于候选覆盖，scene 3 中特征模长可能携带运动置信度或交互强度。
2. scene 1 出现“Oracle 更好、Top-1 更差”，scene 3 则相反，说明 NSCA 改变了编码上下文到 mode logits 的尺度与排序接口。
3. NSCA 不增加实质计算规模，但当前没有精度主线价值。它只保留为未来与 KDTA 的正交组合观察项；只有 KDTA 单独通过后才值得做组合，不应现在扩展三种子。

## 决策

- 默认注意力保持 F16 缩放点积；
- 不运行 NSCA 多种子和更多场景；
- 下一步实现 pair-conditioned KDTA；
- KDTA 首先仍使用点积注意力，避免两个变量混合。
